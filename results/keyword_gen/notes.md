检查各群 settings 与 connection.json 后，对当前启用 generate 的三个群分别运行；测试群当时为 intelligence，不纳入。每组 200 个输入，种子 1，attempts=64，refine=0.30。基线 blend 与线上对应群一致：0、0.2、0。

```powershell
python -B -X utf8 keyword_gen.py compare --db data\production.sqlite3 --group 1050045834 --blend 0 --out runtime\keyword_gen_work_1050045834
python -B -X utf8 keyword_gen.py compare --db data\third.sqlite3 --group 1006808801 --blend 0.2 --out runtime\keyword_gen_work_1006808801
python -B -X utf8 keyword_gen.py compare --db data\fourth.sqlite3 --group 929618496 --blend 0 --out runtime\keyword_gen_work_929618496
```

三个命令并发运行，总共 600 条输入、1200 次模型比较调用。计时包含并发竞争，应视为本机本轮观测值，不是独占基准。三个快照初始 intel_memory 条目数分别为 1138、5000、285，频次权重分别为 1277、6020、298；这不是导出消息总量，也不提供完整训练数据的时间范围。

## 真人盲评：已完成 60 条

2026-10-16，由用户在本地 Excel 中手工填写，未用 AI 代评。由于没有合适留出集，使用正式群 200 条快照对照作为候选。按用户要求选出参考价值较高的 60 条：左右均有回复、规范化输入至少 4 个字母/数字字符、输入不重复，并用字符/二元片段差异及句长覆盖减少重复。按输入长度 <=7、8–14、15–24、>=25 字计，分别选取 16、21、18、5 条。

选样不读取模型身份或答案映射，不依据哪一方获胜。Excel 保留原始编号和随机左右顺序，模型身份不显示。此为有目的的诊断选样，**不是随机样本**；全部来自已训练的 intel_memory，且排除了无回复条目。因此结论只适用于这 60 条双方均有回复的输入，不能代表全体 200 条、无回复取舍或未见过的输入。

核验 Excel 中 60 个唯一编号与原表相符，60 条均有有效评分；4 个回复单元格仅少了首尾普通空格，其他正文和左右顺序未变。只将评分按编号映射回原 TSV，保留 TSV 的原始文本；Excel 与带原文的 TSV 均只保存在本机。随后运行：

```powershell
python -B -X utf8 keyword_gen.py tally --out runtime\keyword_gen_work_1050045834
```

| 真人选择对应模型 | 条数 | 占已评 60 条比例 |
|---|---:|---:|
| keyword 原型胜 | 22 | 36.67% |
| baseline 旧模型胜 | 21 | 35.00% |
| 差不多 | 2 | 3.33% |
| 两条都差 | 15 | 25.00% |

净胜率按请求公式 `(22-21)/60` 为 **+1.67%**，程序保留四位小数为 0.0167。原 TSV 仍包含 200 对，judged=60、blank=140、invalid=0；其余 140 条未评，不应计为平局或两条都差。只看有明确偏好的 43 条，原型为 22/43，约 51.16%，分母与请求的净胜率不同。

**解释：这轮盲评基本持平，原型只多赢 1 条，没有证据支持其自然度明显优于旧模型。** 15/60 条两条都差，说明即使双方都有输出，仍有相当比例的回复未被评审认可。自动指标改善没有转化为本轮明确的人类偏好优势；不据此上线。若继续研究，优先补充近期群聊留出集与独立真人评审，再验证生成质量。没有把未写出的评分理由猜成具体语义失败类型。
