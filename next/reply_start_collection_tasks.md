# 接话开头研究：下一步先取得明确引用关系

2026-10-09。依据本轮 `runtime/continuation_reply_work/experiment.md`。当前不将条件起句模型部署到生产。以下是下一轮可交给低成本模型的机械任务；先做离线组件和模拟事件测试，交付即停。

## 问题与边界

旧文本导出只有时间、作者和正文，没有被回复消息的 ID。相邻、同话题、@同一个人都不能证明回复的是特定一句话。本轮两种条件首字探针没有足够正向证据。

当前 `qbot.py` 在 `handle` 中只接受全为 `text` 的消息段；`reply`、`at` 等段会导致其跳过。这是现有策略，不在本任务中更改。不能直接移除检查，不能把旧的昵称字符串当真实 OneBot 元数据。

OneBot 11 的 `reply.data.id` 是引用消息 ID；`at.data.qq` 是被@的QQ号。只有前者能指向一条特定消息。仍须根据本地已知消息验证群、作者和时间；明确引用也不自动保证内容是一问一答。[官方消息段规范](https://github.com/botuniverse/onebot-11/blob/master/message/segment.md#回复)

只在 `D:\Projects\QBot\runtime\reply_capture_work` 写文件，所有临时与缓存到D。禁止在这轮改生产代码、DB、连接NapCat、发送QQ消息、补拉消息或启停服务。不得修改两轮旧结果或清空数据库。代码不能包含Sender、QQ请求客户端或任何发消息路径。

## 1. 实现纯内存离线收集组件

建议文件 `reply_evidence.py`，API由调用者传入已规范化的事件，组件本身不接网络。

构造参数：机器人QQ号、固定发送/处理白名单、实际启用观察的群、单群上限1000条、TTL180秒。实际观察群必须是白名单子集；默认空集（不观察）。禁用开关不改变任何外部RNG、模型、用户质量分或封禁状态。先判断消息路由，再读正文；非群事件、其他群、self_id不符一律返回空且不缓存。

消息键为 `(group_id, message_id)`，禁止单独以message_id索引；QQ号、群号、消息ID必须独立规范化，拒绝布尔值、缺失和不合法字符串。时间须为有限数，缓存按本地单调到达时钟维护TTL；事件时间用于验证原消息在当前消息之前，不能以自称时间延长缓存无限保留。

缓存仅容纳调用者明确标记为已允许训练的、合格的原始人类文本消息。调用者需传入训练许可与来源，不允许组件自行假定“未发现门禁=允许”；00封禁、拒绝训练、命令、媒体、不合格文本、机器人消息不缓存。默认许可False。保存作者QQ、时间、规范化正文和来源标志，不保存昵称到正文。

当前消息若有恰好一个结构化reply段，查同群缓存中的原消息。缺失、过期、同作者、自身引用、原作者是机器人、引用目标被拒训练、时间矛盾、重复message_id，一律跳过，不请求`get_msg`补齐、不推断其他群来源。

当前正文只从可信结构化text段拼接；reply段不作为正文。at段只是元数据，不能转成昵称加入正文。只允许与已知引用目标作者一致的附带at，多个不同目标或at=all跳过。face/image/file/forward等其他段存在时跳过。字符串形式的原始CQ码不解析，不把用户发的`[CQ:reply,...]`当引用。

当前消息同样要求调用者明确给出训练许可；若现有主流程因reply/at拒绝训练，离线模拟可以测试结构，但不得声称该消息已通过现有生产训练策略。收集器不擅自抽用户质量概率，不消耗生产RNG。未来要接入时必须先设计“正文检查、训练许可、引用证据”三者怎样共享判断，不能偷偷绕过门禁或质量制度。

组件只返回一条证据对象：同群来源、两条ID/作者/时间、输入正文、响应正文、`evidence_type=structured_reply_reference`、双方许可来源。这表示引用关系，不标`human_verified=true`，也不标语义“优质问答”。此轮返回对象只用于模拟，不写真实群原文。

## 2. 区分机器人原文与其他账号复读

可单独实现 `recent_bot_echo.py`：只接收调用者传入的已成功发送的机器人文本指纹，按群保留180秒；不向QQ发送内容。只检测至少12个字符的较长完整文本一致（允许去空白、去末尾常见标点，但必须写明这种规范化的影响）。纯哈哈/喵喵等表达性文字不能仅凭匹配就称恶意。

它只能给训练样本一个“与近期机器人文本一致”的来源标记，不能扣分、触发门禁提示或自动封禁。即使将来决定不学习该样本，也不是对用户违规的判断。

本轮已发现16条这种匹配，见`echo_audit.json`。这些是线索，不证明复制意图；账号也可能被人工发言。不能根据聚合chars/qa权重反推历史来源并删库。

## 3. 修正下一份离线派生语料

新建独立加载器，不覆盖旧实验：

1. 从原始QQ导出保存的作者元数据排除确认的系统记录。本文件对应的导出账号10000与1000000，昵称均为系统消息；不能仅因正文出现“加入本群”或“撤回”就删掉真实人类讨论，也不能把任意昵称叫系统消息的人等同系统。
2. 原始记录仍保留其索引与位置，所有被排除事件都是对话隔断；不能压紧数组后生成新邻近配对。
3. 对明显裸媒体/表情占位保守隔离，披露方括号纯文本可能被误删；不将它变成生产门禁规则。
4. 机器人账号消息永不学习；近期相同文本标记另作消融，不混成“所有人类复读都是恶意”。
5. 保持现有门禁、强重复预处理和时间切分。历史质量/封禁无法重建，继续明确100分代理及其他限制。
6. 旧锁定提示中系统记录必须剔除并列出索引，本轮发现旧测试40提示中的1条属系统。不要偷偷另抽更好提示来补足40。更正语料后的结果须重新比较同一更正基线，不能与旧表直接作算法效果比较。

## 4. 有意义的离线测试

至少覆盖：禁用不读取正文/不缓存；私聊/非白名单/停用群零缓存；相同message_id跨群隔离；00/训练拒绝原消息不能成为引用目标；机器人目标、同作者、自引、过期、时间异常和重复事件跳过；一条合法引用建立准确索引关系；附带at目标一致/冲突；图文混合、转发、原始CQ字符串拒绝；昵称不进入正文；TTL与单群上限；质量许可缺失时默认拒绝；组件不修改调用者的生产RNG。

使用模拟事件，不登录QQ、不向测试群发内容。测试群只作为模拟group_id，不能因此调用真实发送API。

## 5. 交付与后续研究门槛

交付组件、测试、接口说明、数据更正清单、源哈希与完整限制。所有实际接入默认不发生；没有足够真实证据不生成“模型升级成功”公告。

将来获得数据后，先分开评价：明确结构化引用、精确文本称呼、仅时间邻近。不能把三层数量相加后全部称真人问答。新验证/测试按时间留出，避免继续将现有小测试集调到好看。

条件起句只存/抽首1–3字或短词组；不得检索整句答案。正文的可读性单独评估，不能用首字分布变化证明说人话。若要进一步研究词级/短块生成，另开一个受控离线条件，别与EOS、起句、清库和处罚同时上线。
