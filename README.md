# QBot 本地 QQ 机器人

使用 NapCat v4.18.28 + Python 3.12 标准库 + SQLite。项目目录为 `D:\Projects\QBot`。
无需注册官方机器人。QQ 登录通过本地 NapCat，优先扫码；程序只从 `qq.txt` 首行读取账号，未使用密码。

## 会话限制

发送白名单硬编码为 **312579123（测试）**、**1050045834（正式）** 、**1006808801** 和 **929618496**。用户已明确允许 QQ 底层接收其他会话；其他群和所有私聊一律不回复、不学习。真实测试只在测试群进行。

1. 入口先检查事件类型、群号和账号，再提取正文。
2. 出口仅允许 `send_group_msg`，按白名单重新构造纯文本消息，不接受调用者提供的其他 API 字段；回复目标必须与来源群一致，CQ 字符串不会被解释成 @ 或其他动作。
3. 项目内的 NapCat `MsgApi.sendMsg` 额外加入四群白名单校验，拒绝其他群和私聊；启动前校验模块哈希。不能直接替换/升级 vendor 后绕过校验。
4. 所有服务只监听 `127.0.0.1`，API 使用随机 token。HTTP 事件需要 HMAC 签名，支持 NapCat 实际使用的 chunked 分块传输及秒/毫秒时间戳；回调永远返回 `{}`，不用隐式回复原会话的快速操作。用事件时间计算相邻消息的 3 分钟间隔，不额外依赖本机时钟拒绝消息；重复事件按消息 ID 去重。
5. NapCat 消息日志关闭。没有欢迎消息、好友自动通过、定时发言、历史消息抓取或附加插件。发送异常不自动重试。

这些措施覆盖本项目的机器人发送路径；它不是 QQ 客户端底层不收消息的保证，也不能约束用户在其他 QQ 客户端手动发送消息。

## 使用

Windows 下直接双击项目目录中的 `start.cmd` 启动、`stop.cmd` 关闭、`status.cmd` 查看状态。后台进程隐藏运行，脚本窗口显示结果后按任意键关闭。启动会自动解除 STOP，无需手动删除；启动前仍强制检查四群发送保护。已在运行时不会重复启动，启动失败会回滚本次进程并恢复 STOP。

命令行自动调用可使用 `start.cmd --no-pause`、`stop.cmd --no-pause`、`status.cmd --no-pause`。仅检查启动条件、不实际启动：`powershell -NoProfile -ExecutionPolicy Bypass -File .\start-live.ps1 -CheckOnly`。

```powershell
cd D:\Projects\QBot
python -X utf8 -m unittest -v
.\vendor\napcat\node.exe .\test_napcat_guard.cjs  # 不登录 QQ 的底层发送保护测试
.\start-local.ps1  # 仅离线控制台，使用独立的 offline.sqlite3
.\start-live.ps1   # 启动真实接入，二维码登录
.\stop-live.ps1    # 停止本项目 NapCat，并设置 STOP 开关
python -X utf8 login_status.py  # 仅查询登录状态，不输出账号或密钥
python -X utf8 login_status.py --refresh-qr  # 二维码过期时刷新
```

停止后再次启动，双击 `start.cmd` 即可。停止脚本只关闭本项目的进程，不终止其他 QQ/Python 程序。停止开关无法撤回已经提交的网络请求。等待启动窗口中 `isLogin=true`、`coreReady=true` 后再向群内发命令；启动前的旧消息不会自动补执行。
二维码文件位于 `vendor\napcat\napcat\cache\qrcode.png`。扫码后应由其他 QQ 账号在测试群发消息测试；机器人账号自己发送的消息会被排除。
`python -X utf8 smoke_test.py` 只向测试群 **312579123** 发送一条连接测试消息，日常启动不需要运行它。正式群不发送测试消息。
测试群数据库为 `data\live.sqlite3`，正式群数据库为 `data\production.sqlite3`，群 **1006808801** 为 `data\third.sqlite3`，群 **929618496** 为 `data\fourth.sqlite3`（新增群从独立空库开始学习）。各群的模型状态、match 问答、generate 在线学习、intelligence 上下文和封禁列表完全独立；原有三群已载入用户授权的相同 generate 预训练数据，新增群不自动复制其他群数据。不要将预训练聊天、数据库、凭据、runtime、vendor 提交到 Git。

## 模型

发送全局限速：四个群合计最多每 **5 秒** 发一条，普通回复、模型切换提示、命令反馈、重启公告和连接测试共用限速。**例外**：`/apply` 的审核回复与白名单到期通知不受该限制（见下节）。冷却期间继续学习、执行命令，但跳过回复，不排队补发；发送失败同样占用一次间隔。限速状态保存在 `runtime\send-rate.sqlite3`，程序重启不会清空冷却时间。

- match、generate、intelligence 三套模型始终同时静默学习有效的人类纯文本消息。match 收集相邻消息 `(q,a,w)`，间隔 **大于** 180 秒才断开，正好 180 秒仍学习；generate 把每条消息内**所有相邻字符**（英文、数字、标点、空格、换行、emoji 同样计入，不同消息之间不连接）计入 `chars`，因此回复带着标点成句，而不是由 `.j`、`\n1` 这类碎片拼出；intelligence 学习整句语境、问答联系和用于检索的字符片段。
- 字符范围只有**一个**口径：写入即全量（`learn_chars`），`generate()` 走图时不再按字符类型筛分。后台大屏另有一个**只用于统计展示**的中文过滤（`is_counted`：汉字与中文标点），它既不改变已入库的数据，也不影响生成；下面的 `GET /api/generate/non_chinese` 是同一口径的只读统计。历史数据里的非中文转移因此始终保留，也始终参与生成。
- generate 的转移另有一张 `user_chars(user_id, first, second, w)` 归属表，记录每个 QQ 产生了哪些转移，供管理后台按 QQ 筛选与下钻。**归属只对写入该表之后的数据生效**，历史数据没有发送者信息，后台会如实显示归属覆盖率。
- `GET /api/generate/non_chinese` 只做**只读统计**，用于在后台显示"大屏图表不展示"的历史转移有多少行、多少权重；这些行仍照常参与学习与生成，系统也不提供删除它们的操作。
- `/model match`：默认回复模式。精确匹配 q，以 `w/sum(w)` 抽样；无候选时不回复。
- `/model generate`：当前消息**末两个字符**作为隐藏起始上下文，其中末字才是走图起点，两个种子字符都不附加到回复；均匀选择 3–50 个新生成字符作为目标长度，每步按后继计数加权抽样。可选双字弱偏置用精确整数混合权重，保留原单字模型中的低频后继。没有后继字则结束；新生成字符不足 3 字不发送，绝不伪造后继。
- **自然收尾与有限筛选**：真实服务中 30% 的回复进入优化分支。只在原轨迹长度后四分之一内的完整句末截取前缀，不添加标点或固定答案；引号/括号、网址、代码、完整省略号等有单独保护。只有第一条有明显循环或未闭合结构时，最多额外生成两条，在可用候选中随机选择；都不合格则回退原回复。基线返回无回复或命中出站禁对时不能被安全前缀“救回”。另外 70% 使用原生成路径，原 RNG 不受分支抽样影响。此项减少结构错误，不代表已经验证了语义理解或真人质量提升。
- **关键字回复（仅第三群 1006808801，30%）**：原 generate 从输入末字往下走，回复读起来是在替对方把句子说完。第三群 generate 模式下 30% 的回复改走 `keyword_reply.py`：从输入里选信息量高的 1–2 字关键字，用 1–3 字上下文（Witten-Bell 插值，上下文须在 ≥2 条不同消息中出现）分别向后走到句尾、向前走到句首，按“走到真实句首句尾 → 接近从真实消息抽样的长度 → 关键字惊讶度”选 64 个候选中最好的一条；与训练消息相同或 ≥80% 照搬单条旧消息的候选丢弃；没有关键字或合格候选时不回复，不退回续写。统计来自本群 `chars` 与 `intel_memory`，内存模型最多 60 秒重建一次，回复发出前逐对复核当前 `chars`，并照常经过出站禁对检查。比例由 `live.py` 的 `KEYWORD_REPLY_PROBABILITY` 控制，改为 `{}` 并重启即完全关闭；比例为 0 的群不消耗该分支的随机数，原 generate 行为不变。离线评测与对比工具见 `keyword_gen.py` 与 [keyword_live_third_group.md](next/keyword_live_third_group.md)。
- **generate 双字弱偏置（默认关闭，方案见 [next_gen.md](next_gen.md)）**：每条有效消息除 `chars` 外，还会记入按群独立的 `gen_trigrams(older, first, second, w)`——同一条消息内的连续三字窗口（长度 m 的消息产生 m−2 个，长度不足 3 不记），字符口径与 `learn_chars` 完全一致，且不跨消息、附件占位符、发送者、群或日期。生成每一步按 `P(c) = (1−λ)·P₁(c) + λ·P₂(c)` 混合，`λ = generate_blend_max × N/(N+4)`、上限 **0.20**，因此单字模型在任何情况下至少占 80%；`P₂` 只在 `chars` 已有的后继上归一化，后台删掉的字符对绝不会被三字表带回来；证据不足（无三字记录、提示只有 1 个字、候选全被删除）时完全退回原单字路径，随机数消耗也与旧版一致。
  - 开关：`Bot(generate_blend_max=…)`，默认 `0.0`，允许 `0.0–0.20`。`live.py` 可从 `runtime/connection.json` 读取**可选**的按群字段 `{"generate_blend_max": {"312579123": 0.2}}`（缺失时所有群为 `0.0`；非法群号、非有限数值或越界值会拒绝启动）。项目本身**不写入**该字段，是否启用由管理员审核后手工配置，因此代码合入后重启仍按旧概率运行。
  - 生产库的三字表**从启用后的消息开始积累**：历史 `chars` 无法反推三字顺序，不做回填。`/train`、`pretrain.py` 与在线学习同口径写入；`/clear generate`、后台 `/api/clear` 一并清空；`/save`、`/load` 的备份包含该表，**旧版备份缺少此字段时按空表加载**（格式版本号不变）。后台 `/api/overview` 已返回 `trigrams` / `trigram_weight` 两个计数字段，大屏暂未展示。
- `/model intelligence`：轻量的相似语境检索＋1–4 字上下文拼接，不依赖大型预训练模型。优先从相似发言的历史回复生成，无相关证据时不强行回答；输出 3–50 个新字符。每群最多保留 5,000 条语句、20,000 条联系，单条超过 512 字时不进入 intelligence。详细方法、边界与性能见 [INTELLIGENCE_DESIGN.md](INTELLIGENCE_DESIGN.md)。
- 机器人自己的消息、重复消息和命令不进入语料。切换模式只改变回复方式，保留 match 前文；重启、图片等非纯文本消息和 `/clear match` 会断开前文。模式持久化，match 的临时前文不跨进程恢复。历史预训练仍仅写入 generate，不自动回填 match。
- 当前允许测试群成员使用 `/model` 切换模型；`/apply` 任何群成员都可用；`/clear`、`/ban`、`/unban`、`/dstx`、`/save`、`/load`、`/train` 仅限管理员 QQ **575586491**。
- `/clear match`、`/clear generate`、`/clear intelligence`：仅 QQ **575586491** 可调用，只清空命令所在群的指定模型，另一群和其他模型不受影响，也不切换当前模型。match 和 intelligence 各自重置自己的前文；generate 包括清空预训练权重、三字窗口表 `gen_trigrams` 及导入标记，之后不会自动重新预训练，需要时可手动重新导入。保留消息去重记录，重复上报的 clear 不会再次清空。任何 clear 命令均不参与学习。执行不受回复限速影响，确认提示仍遵守全局 5 秒间隔。
- 图片、语音、文件、@、引用等非纯文本消息不参与学习或回复。这里的字符指 Python Unicode 码点，组合 emoji 可能含多个码点。

## 管理与封禁命令

**用户质量分**：质量分按 QQ 跨群共用，初始 100。门禁发现只形成待审报告，不自行扣分；审核批准或后台人工设分后，训练与模型回复分别按分数 `i%` 独立抽样。历史 01/02 事件保留为 `legacy` 只读记录。研究与备份细则见 [QUALITY_SCORE_RESEARCH.md](QUALITY_SCORE_RESEARCH.md)。

`/score` 查询自己的质量分等级：100 为无可挑剔、85–99 优秀、70–84 良好、60–69 中等、40–59 较差、0–39 很差。每个 QQ 在四个授权群之间共用每周两次额度，每周一北京时间 00:00 自动重置。返回剩余额度；用完后返回下次重置时间。命令不训练、不触发表情；仍受 00 封禁和全局 5 秒限速约束。明确被限速跳过的查询不扣额度，发送结果不确定时保留已占额度以免重复查询。

**门禁流水线 v2**：00 对已封禁用户完全静默拦截，不建 00 报告、不重复扣分；01 长消息及 02 敏感词只阻断训练和模型回复，默认不发群提示、也不自动扣分/封禁。01 分拆、03 长英文/网址、04 单条短重复、05 五条同关键词、06 明确训练后补全测试、07 高频发言/图片先以观察模式在后台收集待审报告，不改变消息处理。所有报告在“用户质量分”页人工审核；批准后一次性扣分和可选短封禁，拒绝则删除。审核历史显示签名快照。完整阈值、误伤约束与迁移口径见 [gate_pipeline_v2.md](next/gate_pipeline_v2.md)。

2026-10-09 记录复核版 `gates-v2.1-record-review`：04 的笑声/语气重复、明确引用重复，建议扣分为0；02 紧邻命中词的明确反对或词义讨论，建议扣分与封禁为0，仍保留检测与训练过滤，交人审。历史报告与既有分数不重算。研究与版本对应见 [continuation_record_research.md](next/continuation_record_research.md)。

**表情包缓存（测试阶段）**：仅接收 NapCat 明确标记的自定义/商城表情，下载到 `data/stickers`，按群隔离，单张不超过 2 MiB、每群至多 200 张、最长暂存 7 天；普通图片不进入缓存。根据表情出现时的同群文字建立弱关联。模型文字成功发出后，优先用生成的回复匹配表情，也参考用户原话及近邻前文；有明确关联的重复表情以 25%–30% 概率发送，仅原话关联为 16%，只出现一次的自定义表情必须满足更强的回复片段匹配，概率为 14%。这些是匹配后的条件概率，不是所有回复都会抽表情。每群至少间隔 3 分钟，图片仍受全局 5 秒发送间隔约束；优先按表情子类型发送，明确失败才退回普通图片。无文字关联的缓存不会随机发送；关联依赖聊天共现，不做视觉理解或 OCR。

`/ban`、`/unban`、`/save`、`/load`、`/train` 与 `/clear` 一样仅 QQ **575586491** 可调用；其他账号只收到无权限提示。所有命令都在群内给出中文反馈，命令本身从不进入语料。

- `/ban QQ号 秒数 [原因]`：封禁 1–31536000 秒。被封禁账号的消息既不进入任何模型训练，也不会得到任何回复；封禁按群隔离，只影响命令所在群。不允许封禁管理员账号。反馈形如 `已封禁。123456789（QQ号），您已被封禁2 小时，原因：管理员封禁，方式：手动封禁`。
- `/unban QQ号`：移出封禁列表，立即恢复正常学习与回复；不在列表时也会明确反馈。到期封禁在下次收到该账号消息时自动清除。
- `/dstx`：一键“大赦天下”，解除**所有群**的封禁名单，不只限命令所在群。输出首行 `大赦天下！解除封禁名单：`，其后为 `1. QQ号`、`2. QQ号`……；同一账号在多个群被封只列一次，并按 QQ 号数值升序排列。没有封禁时输出 `（当前没有封禁记录）`。名单过长时按条截断并提示总数。多个群的机器人实例在启动时互相登记（`Bot.attach_peers`），因此这个命令需要各群实例同时在线。
- **自动封禁（五级十三档）**：收到色情词汇时按词条等级封禁发送者，等级从 **Ia（1 分钟）**到 **Vb（24 小时）**，共 **13 档**；同一账号 **30 天内**每有一次违规，等级上浮一档，封顶 Vb。完整档位阶梯、各级词条与累犯示例见 [BAN_GRADES.md](BAN_GRADES.md)。反馈形如 `123456789（QQ号），您已被封禁12 小时，原因：色情词汇「几把」（IVb级·严重），方式：自动封禁`。
  - **每级至少两个子档**：累犯可以逐档加重，不会出现"第二次就直接封顶"的跳变；相邻档位近似倍增（1/3/5 分钟 → 10/20/30 分钟 → 1/2/3 小时 → 6/12 小时 → 18/24 小时）。
  - **泛化单字一律不匹配**：`草`（草稿/操场/草莓）、`吊`（吊车/吊销/吊坠）、`逼`（牛逼/逼近）、`屌`（屌丝）都不会单独触发封禁。仅 `屄`、`肏` 两个**无任何正常含义**的字保留在词库中。
  - **量词搭配也排除**：`几把` 同时是量词，`好几把`、`十几把`、`几把椅子`、`几把钥匙` 等一律不触发。
  - 正式/学术词（`色情`、`淫秽`、`性欲`）刻意放在最低档 Ia，误伤成本只有 1 分钟；只有可能专用于骚扰的词条才在高等级。
  - 触发封禁的那条消息本身不会被学习。管理员账号豁免自动封禁，且不能被手动封禁。
- `/save 名称`：把命令所在群的训练数据（match 问答、generate 字符转移与三字窗口、intelligence 记忆/词条/联系、预训练导入标记）导出到 `pre\名称\data.json`。
- `/load 名称`：先清空该群全部训练数据，再载入该备份。封禁列表、当前模型和消息去重记录不会被清除。写于三字表上线之前的旧备份没有 `gen_trigrams` 字段，按空表载入，其余内容照常恢复。
- `/train 文件夹/文件名`：读取 `pre\text\文件夹\文件名.txt`（QQ 文本导出格式；无时间头时按每行一条纯文本处理），对 match、generate、intelligence 三套模型做**增量**训练，不清空既有数据。文件直接放在 `pre\text` 下时也可用 `/train 文件名`。导出中的命令、机器人自身消息、已封禁账号的消息会被跳过。文件很大时该命令会长时间占用机器人，期间不处理其他消息，建议在群内安静时执行。
- `/train list`：首行固定为 `可训练数据集：`，其后每个文件夹名占一行，该文件夹内的文件各以 `- ` 开头列在下面，并隐藏 `.txt` 后缀（其他扩展名原样显示；不含任何文件的文件夹跳过；直接放在 `pre\text` 下的文件排在最后）。`list` 是保留子命令，不会去训练名为 `list.txt` 的文件，但 `文件夹/list` 仍可正常训练。输出超出单条消息长度上限时按“整组”截断（不会出现只有文件夹名而没有文件的情况）并提示总数。

```text
可训练数据集：
xxx
- yyy
- zzz
www
```

- 名称只允许中英文、数字、下划线和连字符，长度 1–32，禁止路径分隔符、`.` 与 `..`，因此无法写到 `pre` 目录之外。
- **启动更新公告已关闭**（`live.py` 的 `ANNOUNCE_RESTART = False`）。原先每次启动会向所有允许的群各发一条更新日志，现按群内要求停发；`broadcast_restart` 与 `RESTART_NOTICE` 仍保留并有单元测试覆盖，把该开关改回 `True` 即可恢复，无需改动传输层。

## 管理后台

本机可视化后台，**作为独立进程运行，不由机器人托管**：

```powershell
.\start-admin.cmd    # 启动（双击亦可）
.\status-admin.cmd   # 查看状态
.\stop-admin.cmd     # 停止
.\start-admin.ps1 -CheckOnly   # 只检查不启动
```

```
http://127.0.0.1:5703/
```

### 为什么拆成独立进程

机器人每次重启都有一段**消息黑洞**（停止 → 启动 → NapCat 登录 → 数据包钩子就绪，约 1–2 分钟），这段时间群里的消息不会被转发、也不会补做。如果后台寄生在机器人进程里，那么**每次改后台或改后台后端都必须重启机器人**，等于每次调面板都让群哑一次。

拆开之后：

- 改 `web\admin.html` **本来就不需要重启** —— 后台每次请求都从磁盘重新读取该文件，刷新浏览器即可
- 改 `admin.py` 后端只需 `stop-admin.cmd` + `start-admin.cmd`（约 1 秒，PID 变化），**机器人完全不受影响**
- `stop-admin.ps1` 只结束命令行里含 `admin.py` 的 python 进程，不会碰 NapCat 或机器人
- `stop-live.ps1` / `start-live.ps1` 也不碰后台，两者互不干扰

`start.cmd` / `stop.cmd` / `status.cmd` 会**同时**处理机器人与后台，作为"全部启停"入口；只想控制后台时用上面三个 `-admin` 脚本。

**仅监听 127.0.0.1，按需求不设密码。** 因此该端口绝不能对外暴露：任何能连上回环地址的程序都可以调用全部接口。前端页面位于 `web\admin.html`，可离线打开（无任何 CDN 依赖）。

门禁 PDF 报告使用项目内 `vendor\pdf-env` 的 ReportLab/Pillow/PyPDF/PyMuPDF 依赖，标题读取系统已安装的**华文中宋**，正文标题用黑体，正文用宋体与 Times New Roman。若迁移到另一台 Windows 主机，需先在 D 盘项目内建立该虚拟环境并安装 `reportlab==4.4.9 pillow==11.3.0 pypdf==6.1.1 pymupdf==1.28.2`；不依赖外部 PDF 服务。控制台以同一份 PDF 渲染清晰的逐页图像，亦可单独打开完整 PDF；报告内容不写临时 PDF 文件。

页面分六个标签：

| 标签 | 内容 |
|------|------|
| **数据大屏** | 各群指标卡、分组对比条形图、覆盖率表格（问答/转移/记忆/封禁/白名单/违规/去重/库大小） |
| **封禁管理** | 封禁名单（剩余时间、原因、方式）、手动封禁/解封、一键大赦天下、白名单发放与撤销、违规日志、切模型 |
| **训练管理** | match 面板（问答对与答案权重条形图）；generate 面板（总量指标、log10 权重分布直方图、Top 转移、异常值面板、单字热力图 + 转移网络图、权重增减表单） |
| **门禁管理** | 00–07 各项目、细分类别、当前模式、建议扣分和短封禁；02 分级词库及排除词组仍可展开查看 |
| **用户质量分** | 按 QQ 号查询/手动设分；以正式 PDF 报告单预览门禁发现，在 PDF 下方填写审核意见，批准一次性扣分或短封禁、驳回删除，历史报告保留签名快照 |
| **系统** | 运行时长、进程信息、STOP 开关状态、各库文件大小、日志尾部 |

**generate 权重调整**：可对「两字（前-后）」或「整句（每相邻两字）」按**当前模型总权值的百分比**增减。削减后若权重 ≤ 0 则**删除该行**。调整幅度不足 1 时增加操作至少推进 1，避免「提交了却毫无变化」。

**异常值判定**：权重分布是重尾的，因此用 **log10(权重) 的 median/MAD 稳健 z 分数**，阈值 ±3 标出异常高值与低值，而不是用均值/标准差（会被极值带偏）。

后台写入使用**每次请求独立、用完即关**的 sqlite 连接（`admin.connect` 是上下文管理器），与机器人的长连接并存，由 SQLite 串行化；写冲突返回错误到页面，不会阻塞服务。

### 强重复段压缩与记忆清理

新训练先通过 `repetition.strong_repeat_repair`：2–12 字片段连续重复至少4次、重复段至少24字，或非语气单字连续至少16次时，保留首次出现和其余正文，删除多余重复。普通笑声、语气词、数字、网址和代码不自动压缩。压缩后的同一文本用于三模型训练；记录压缩条数与删字数，不修改用户质量分。原用户消息仍用于门禁、命令和回复语境。`/train` 对附件分隔的文本逐块应用同一处理。

历史自动清理每5分钟扫描每群最多5,000条记忆，只选择上述强重复段占整句至少80%的条目，每群每轮最多20条。先以 SQLite backup API 保存快照，成功后再删除对应 `intel_memory/terms/links` 和包含该句的 `qa`。备份失败或训练事务未结束时推迟；备份在 `data/backups/memory-clean`。

旧记忆次数与字符计数可能来自不同训练时期、清空操作或导入批次，不是可靠来源账本，因此历史清理保护 `chars/gen_trigrams/user_chars`，不会按记忆次数扣回共享权重。旧字符图里的污染需靠生成筛选减少影响；精确回滚字符来源需要另外的来源记录，当前不会猜算。

控制台支持原始整数 ID（包括大于1000的记录），先预览后执行；预览与目标群、所有待删数据绑定。换群、选择变化或源数据变化均使预览失效。执行前再次验证并备份，防止把旧群记录 ID 提交到新群。

### 输出封禁对（prev, next）

后台「门禁管理」页可维护**出站封禁对**：一旦生成结果中出现指定的相邻两字 `(prev, next)`，机器人**立即截断生成并放弃整条回复**，不发送任何内容。

- **按群独立**：存在各群自己的 `pair_bans(first, second, reason, created_at)` 表里，卡片自带群选择器。
- **守卫在出站路径上**：`Bot.generate` 每走一步都检查新形成的字符对，命中即停止并返回 `None`；此外 `Bot.handle` 在返回前还会对**三种模型**的最终文本各做一次检查，所以 match 与 intelligence 的整句回复同样受控 —— 被禁的字符对不可能被发出去。
- **只过滤模型生成的内容**：封禁通知、`/apply` 反馈、`/model` 提示等系统固定文本**不受影响**，否则一条封禁对就能把命令反馈静默吞掉（有专门测试守着这一点）。
- 面板显示每个封禁对在当前模型里的**权值**；显示「未收录」表示该对不在模型里、生成永远走不到它，这条封禁只是一层保险。
- 添加时前后字都必须是**恰好 1 个字符**；重复添加是更新原因而不是报错。

校验：`python -X utf8 check_ui.py` 会检查页面内联脚本语法、外部依赖、`maxlength`（输入法）、以及自动刷新白名单是否仍然排除训练页与封禁页。

## /apply 白名单

任何群成员都可以使用 `/apply` 申请临时豁免。豁免期内该账号的发言**完全不做色情词汇检测**，因此不会被自动封禁；消息仍照常进入三个模型学习。

- 每次申请在 **30 秒–1 小时**之间随机发放。每群最多同时有 **3 个**有效豁免，每个账号**每天最多成功一次**（滚动 24 小时）。
- 通过时回复：
  ```
  xxx（QQ号），经自动审核，已成功发放x分x秒白名单资格
  当前白名单列表：
  1. xxx（QQ号），剩余x分x秒
  2. xxx（QQ号），剩余x分x秒
  ```
- 失败回复三选一，按此优先级判断：**已经成功申请过** → `xxx（QQ号），您今天已成功申请过，无法发放第二次白名单资格`；**24 小时内有自动封禁记录** → `xxx（QQ号），由于最近24小时内有违规行为，暂无法发放资格`；**名额已满** → `xxx（QQ号），由于白名单列表已满，暂无法发放资格`。
- 到期后由后台定时器（`live.py` 的 `watch_expiry`，每 2 秒一轮）移出白名单并发送 `xxx（QQ号），白名单资格已到期，已移出白名单。`
- **`/apply` 的全部通知（发放、拒绝、到期）不受 5 秒全局限速约束**，避免被聊天限速挡住。为防止刷屏，同一账号 60 秒内的重复申请会被**静默忽略**（不回复、不改变状态）。
- 到期清理由定时器独占：主线程只判断"是否仍然有效"，不删除过期行，否则与定时器抢跑会吞掉到期通知。定时器只在通知**发送成功后**才删除该行；发送失败保留，下一轮重试。
- 定时器使用**自己独立的 sqlite 连接**（每个群一个），因为 sqlite3 连接不能跨线程共享。豁免状态与封禁一样**按群隔离**。

```powershell
python -X utf8 pretrain.py

```
